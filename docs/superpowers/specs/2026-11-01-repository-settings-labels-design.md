# 仓库设置与标签批量操作设计

## 背景与目标

现有工具只支持对选中的 Gitee 仓库进行 README 文本替换。此次扩展让仓库所有者无需逐个打开网页，即可：

- 分别修改选中仓库的显示名称；
- 将选中仓库批量设置为公开、私有，或保持可见性不变；
- 向选中仓库批量追加仓库标签。

继续复用左侧仓库选择、本机会话、逐仓库进度、失败重试和报告能力。所有测试使用假适配器或模拟 HTTP，不对真实仓库执行写入。

## 范围

本轮包含仓库设置、仓库标签，以及支撑它们的通用批量执行结构。

本轮不包含：

- 修改仓库 URL 路径 `path`；
- 替换或删除已有仓库标签；
- 文件或图片上传；
- Issue 标签和 Git 版本标签；
- 真实 Gitee 仓库的自动化写入测试。

## 当前结构约束

`src/readme_batch/platforms/gitee.py` 中的 `Repository.name` 实际来自 Gitee 的 `path`，现有 README 请求依赖它构造仓库 URL，因此不能改变其含义。`src/readme_batch/batches.py` 同时包含 README 预览、提交、并发和重试逻辑，新功能不应伪装成 README 差异批次。

## 方案概述

抽出通用 `RepositoryExecutor`，负责有限并发、临时错误与限流重试、认证失败后停止排队任务，以及逐项成功/失败回调。

- 现有 `BatchManager` 保留 README 快照、差异、SHA 冲突和丢失响应核对逻辑，但调度与重试复用 `RepositoryExecutor`。
- 新增面向非预览写操作的 `OperationManager`，使用同一个执行器，提供设置和标签任务的创建、查询与单仓库重试。
- 不统一现有 README 批次和新操作的公开状态模型，避免为了抽象破坏已有预览语义。

默认三个 worker，最多三次尝试，退避策略沿用现有实现。设置和追加标签均可安全重复执行；自动重试使用完全相同的参数。

## 数据模型

### Repository

保留现有字段并新增：

- `display_name: str`：来自 Gitee 仓库响应的 `name`；
- `private: bool`：来自 Gitee 仓库响应的 `private`。

现有 `name` 仍表示 URL 路径，`full_name` 仍使用路径形式。仓库列表本地 API 返回新增字段，原有字段保持不变。

### Operation

新操作任务包含：

- `id`、`kind`（`settings` 或 `labels`）、`state`（`running` 或 `complete`）、`created_at`；
- 每个仓库一项，状态为 `pending`、`running`、`success` 或 `failed`；
- 每项包含 `error` 和 `retryable`，用于展示失败原因及决定是否提供重试；
- 任务保存创建时的参数快照，后续表单编辑不影响运行中任务。

本地 API 不返回访问令牌或完整敏感请求内容。

## Gitee 适配器

### 更新仓库设置

调用 `PATCH /repos/{owner}/{repo}`：

- 仅修改名称时，发送新的 `name`；
- 仅修改可见性时，发送当前 `display_name` 和 `private`；
- 两者同时修改时在同一请求中发送；
- `public` 映射为 `private=false`，`private` 映射为 `private=true`；
- 任何情况下都不发送 `path`。

成功响应无需转化为提交信息；设置任务完成后由界面重新加载仓库列表，以服务端数据为准。

### 追加仓库标签

调用 `POST /repos/{owner}/{repo}/project_labels`，请求体为标签名数组。使用追加接口而非 `PUT`，因此保留仓库已有标签。

## 本地 API

现有 `/api/batches` 行为保持兼容，新增：

### `POST /api/operations/settings`

请求：

```json
{
  "selected": ["owner/repo-1"],
  "names": {"owner/repo-1": "新的显示名称"},
  "visibility": "keep"
}
```

`visibility` 只允许 `keep`、`public`、`private`。所有 `selected` 和 `names` 中的仓库必须已加载；`names` 的键必须属于 `selected`。名称去除首尾空白后不能为空。

后端排除名称未变化且可见性未变化的仓库。若最终没有实际变更，返回 400。成功创建返回 202 和任务 ID。

### `POST /api/operations/labels`

请求：

```json
{
  "selected": ["owner/repo-1", "owner/repo-2"],
  "labels": ["Java", "Spring Boot"]
}
```

后端去除标签首尾空白、忽略空项并按首次出现顺序去重。仓库必须已加载，至少选择一个仓库和一个非空标签，否则返回 400。成功创建返回 202 和任务 ID。

### 查询与重试

- `GET /api/operations/{operation_id}` 返回任务和逐项状态；未知 ID 返回 404。
- `POST /api/operations/{operation_id}/retry` 接收 `full_name`，仅重试该任务中标记为可重试的失败项；任务运行中或项目不可重试时返回 409。

所有新写接口继续使用现有本机进程令牌、Host、Origin 和 Sec-Fetch-Site 防护。

## 执行与异常行为

- 每个仓库独立执行，一个仓库失败不取消其他仓库。
- 网络错误、服务端临时错误和限流按现有策略自动重试；其他错误直接失败。
- 认证失败后，尚未开始的仓库不再发送远端请求，统一显示认证失败。
- 权限、参数等不会因原样重试而恢复的错误不显示重试按钮；用户需修改参数后创建新任务。
- 手动重试只重新执行一个失败仓库，不重复成功项。
- 新会话或退出登录使未完成任务失效；已经提交的远端请求无法撤销，但结果不得写入新会话任务。
- 报告记录任务类型、仓库、状态、错误和时间，不记录访问令牌。设置与标签报告沿用 JSON 原子写入方式。

## 界面

右侧增加“README 替换 / 仓库设置 / 仓库标签”页签，共用左侧仓库列表和选择集，切换页签不清空选择。现有 README 行为保持不变。

### 仓库设置

- 仅列出选中仓库，每行显示只读路径、可编辑显示名称和当前公开/私有状态。
- 顶部提供“保持不变 / 全部公开 / 全部私有”。
- 执行前展示实际变更清单，自动排除无变化项。
- 包含私有转公开时，确认文字明确显示将公开的仓库数量；用户取消则不创建任务。

### 仓库标签

- 提供标签输入，支持中英文逗号分隔，自动去空白和去重。
- 明确提示“只追加，不清除已有标签”。
- 执行前确认选中仓库数和标签列表。

### 进度与结果

两种操作共用结果展示：等待、执行中、成功、失败和可重试失败。任务运行期间禁止重复提交该任务；任务使用提交时快照，之后编辑表单不会改变任务。设置任务成功后刷新仓库资料并保留仍有效的选择。

## 测试与验收

### 适配器单元测试

使用 `respx` 验证：

- 仓库列表正确读取 `name` 与 `private`，路径语义不变；
- 设置请求正确发送 `name` 和布尔 `private`，且不发送 `path`；
- 仅改可见性时仍发送当前显示名称；
- 标签请求使用追加端点和 JSON 字符串数组；
- 错误映射与令牌脱敏不回退。

### 执行器与任务测试

覆盖并发上限、部分失败、临时错误和限流重试、认证失败停止排队、单仓库重试、成功项不重复执行、任务参数快照和报告。现有 README 批次测试全部继续通过，包括 SHA 冲突与丢失响应核对。

### 本地 API 测试

覆盖空名称、空标签、无实际变更、未知仓库、名称映射越界、重复标签、未知任务、无效重试，以及本机访问防护。验证响应不包含敏感数据。

### 浏览器端到端测试

使用假适配器实际走通：

1. 勾选仓库，修改名称和可见性，确认变更并查看成功结果；
2. 私有转公开时出现明确确认；
3. 输入并去重标签，追加后查看逐仓库结果；
4. 失败仓库可单独重试；
5. 页签切换保留选择，README 原有预览、提交和 XSS 防护无回归。

最终运行完整 `pytest` 套件和 `pyinstaller readme-batch.spec` 构建。交付前检查工作区，删除测试或构建产生且不属于交付物的临时文件。

## 已确认决策

- 本轮先完成设置和标签，文件上传留待后续。
- 采用通用批量执行器，而非两套复制管理器或同步请求。
- 名称逐仓库编辑，可见性批量设置。
- 标签只追加，不提供覆盖模式。
- 不修改仓库路径，不对真实仓库执行自动化写入。
