# 批量上传文件设计

## 背景与目标

现有工具已经支持 README 替换、仓库设置和仓库标签。第二阶段允许用户选择多个本地图片或小文件，一次上传到所有选中的 Gitee 仓库，避免逐仓库打开网页上传。

沿用左侧仓库选择、本机会话、通用并发执行、逐仓库结果、失败重试和 JSON 报告。每个仓库的全部文件只产生一次提交。

## 范围与限制

本轮包含：

- 多文件选择、目标目录、统一提交说明；
- 默认不覆盖同名文件，以及显式覆盖模式；
- 每仓库一次多文件提交到该仓库默认分支；
- 冲突、失败、重试、提交链接和丢失响应核对。

本轮不包含：

- 选择其他分支、删除或移动远端文件；
- 文件夹递归上传或保留本地目录结构；
- 大文件分片、断点续传和 Git LFS；
- 文本差异预览；
- 真实 Gitee 仓库的自动化写入测试。

应用层限制固定为：最多 20 个文件，单文件最大 10MiB（10 × 1024 × 1024 字节），单批总大小最大 25MiB（25 × 1024 × 1024 字节）。空文件允许。浏览器到本地服务使用 JSON Base64，不新增 `python-multipart` 或其他第三方依赖。

## 已确认的 Gitee 接口

新建/更新统一使用 `POST /repos/{owner}/{repo}/commits`，JSON 请求体包含：

- `branch`：仓库默认分支；
- `message`：非空提交说明；
- `actions`：文件操作数组。

每个 action 包含 `action=create|update`、仓库相对 `path`、Base64 `content` 和 `encoding=base64`。访问令牌通过查询参数传递。响应解析提交 SHA 和网页链接。

目标路径预检使用 `GET /repos/{owner}/{repo}/contents/{path}?ref={default_branch}`，路径各段需正确 URL 编码。404 表示可新建，其他错误不得当作不存在。

## 数据模型

新增不可变 `UploadFile`：

- `path: str`：已经校验和拼接的仓库相对路径；
- `content: bytes`：原始二进制内容。

新增 `UploadResult`：

- `commit_info: CommitInfo | None`；
- `reconciled: bool`，表示响应不确定后通过远端内容核对确认成功。

扩展现有操作模型：

- `OperationKind.UPLOAD = "upload"`；
- `OperationItem` 增加可选 `commit_info` 和 `reconciled`；
- `OperationItemState.CONFLICT = "conflict"`，属于终态且不可手动重试。

设置和标签任务的现有响应与行为保持兼容。上传任务在内存中保存不可变文件元组快照，报告和任务查询不包含 Base64 或原始文件内容。

## 本地 API

新增 `POST /api/operations/uploads`，继续使用现有本机进程令牌、Host、Origin 和 Sec-Fetch-Site 防护。

请求示例：

```json
{
  "selected": ["owner/repo-1"],
  "directory": "photo/common",
  "overwrite": false,
  "message": "chore: 批量上传文件",
  "files": [
    {"name": "QQ.png", "content_base64": "iVBORw0KGgo="}
  ]
}
```

处理规则：

- 仓库必须已加载，至少选择一个仓库和一个文件；
- `message` 去除首尾空白后不能为空；
- 文件名去除首尾空白，不能为空，不得包含 `/`、`\\` 或控制字符，不得为 `.` 或 `..`；处理后重复的精确文件名返回 400；
- `directory` 去除首尾空白，空字符串表示根目录；拒绝绝对路径、Windows 盘符、反斜杠、空路径段以及 `.`/`..` 路径段；允许中文和空格；
- 使用严格 Base64 解码，非法内容返回 400；
- 文件数量、单文件和总大小超限返回 413；空文件计为 0 字节，可以上传；
- 所有文件在创建任务前完成验证，任何输入错误都不得创建任务或发送远端请求。

成功创建返回 202 和任务 ID。查询与重试继续使用 `GET /api/operations/{id}` 和 `POST /api/operations/{id}/retry`。上传成功项包含提交信息，冲突项不可重试。

## 路径与 Gitee 适配器

`UploadFile.path` 由规范化目录和文件名拼接，使用 `/` 分隔。Gitee 请求 URL 对完整路径中的各段编码，但保留 `/` 分隔符。

适配器提供 `upload_files(repository, files, overwrite, message) -> UploadResult`，执行：

1. 逐个读取目标路径元数据，区分存在、404 不存在和其他错误；
2. 默认模式下任一文件存在则抛出 `CONFLICT`，并在整个预检结束前不发送提交；
3. 覆盖模式下按实际存在性生成 `create` 或 `update`；
4. 所有路径检查通过后，将原始字节 Base64 编码，在一次 `/commits` 请求中提交全部 actions；
5. 解析提交链接并返回结果。

因此，同一仓库不会因预检发现冲突而只上传其中一部分文件。

## 丢失响应与重试

上传提交遇到临时错误、限流或冲突等不确定结果时，适配器重新读取本批所有目标文件并比较二进制内容：

- 全部与任务快照一致，返回 `reconciled=true` 的成功结果，不再发送重复提交；
- 任一文件缺失或内容不同，重新抛出原错误，由通用执行器决定是否重试；
- 核对请求本身失败时，按原错误处理，不把不确定状态伪报为成功。

手动重试同样执行该核对，避免第一次请求实际已成功时产生重复提交。权限、参数和冲突错误不显示重试按钮；临时错误和限流沿用现有三次尝试与退避策略。

## OperationManager 与报告

新增 `start_upload(repositories, files, overwrite, message) -> str`，保存不可变文件、覆盖开关和提交说明快照。任务提交后修改浏览器文件或表单不影响运行中任务。

通用成功回调记录上传提交信息和核对标记。设置、标签继续返回无提交信息的结果。终态集合包含 `SUCCESS`、`FAILED` 和 `CONFLICT`，只有全部项目终态后才完成任务并写报告。

上传 JSON 报告记录任务类型、仓库、状态、错误、重试性、提交 SHA/URL 和核对标记，不记录文件路径列表、文件内容、Base64、访问令牌或完整参数快照。

## 界面

增加“文件上传”页签，共用左侧仓库选择。切换页签保留文件选择、目录、覆盖开关和提交说明。

表单：

- 多文件选择器；
- 目标目录，默认空；
- 覆盖同名文件复选框，默认不选；
- 提交说明，默认 `chore: 批量上传文件`；
- 文件列表显示名称和大小，不提供文本差异预览。

执行流程：

1. 在浏览器检查文件数量、大小、重复文件名和目录形式；
2. 点击执行时固定文件与表单快照，禁用重复提交；
3. 将文件读取为 Base64，读取失败则停止且不创建任务；
4. 确认信息包含仓库数、文件数、总大小和目标目录，覆盖模式显示额外警告；
5. 创建任务并复用轮询、结果和重试组件。

成功项显示提交链接，核对成功项明确标注。冲突显示同名文件错误且无重试按钮。文件名和错误内容使用 `textContent`，不得注入 HTML。选择仓库或切换页签不得清空文件选择。

## 测试与验收

### Gitee 适配器

使用 `respx` 验证：

- 文本和二进制字节（含 `0x00`、`0xff`）的 Base64 内容；
- 中文文件名和目录的 URL 编码；
- 新建与覆盖动作、默认分支和统一提交说明；
- 默认冲突时没有任何 `/commits` 请求；
- 一个仓库所有文件只有一次 `/commits` 请求；
- 丢失响应后内容一致时核对成功，不一致时仍按错误处理；
- 错误映射和令牌脱敏不回退。

### 任务与本地 API

覆盖不可变文件快照、部分失败、冲突不可重试、单仓库重试、提交信息和报告脱敏。验证非法 Base64、重复文件名、空文件、非法目录、空提交说明、未加载仓库、20 个文件上限、10MB 单文件和 25MB 总大小限制，且无效输入零远端写入。

### 浏览器端到端

使用假适配器和 Playwright 实际上传内存中的文本及二进制文件，走通：

1. 根目录和子目录上传、确认、提交链接；
2. 默认同名冲突和覆盖警告；
3. 临时失败重试及不可重试冲突；
4. 运行中修改文件或表单不改变任务快照；
5. 页签切换保留文件选择，文件名 XSS 仅按文本显示；
6. 现有 README、设置、标签和退出流程无回归。

最终运行完整 `pytest`、`pyinstaller readme-batch.spec` 和打包程序本机启动检查。不得对真实仓库执行测试写入。

## 已确认决策

- 采用 JSON Base64，不新增依赖；
- 每仓库一次多文件提交；
- 默认不覆盖，冲突预检通过后才提交；
- 主要面向图片和小文件，限制为 20 个、单文件 10MB、总计 25MB；
- 通过远端二进制内容比对避免丢失响应导致重复提交。
